SDN File Sharing Console

Concurrent TCP file sharing over a Mininet network with an os-ken controller

Controller Switches

How the system fits together

Clients on h1–h5 talk to a file server on srv over raw TCP sockets. Between them are four Open vSwitch switches that know nothing on their own: every forwarding decision is made by the SDN controller and pushed to the switches as OpenFlow rules. The file server also reports application events to the controller, so logins and transfers change how the network behaves.

What the controller does with a new connection

  1. The switch has no matching rule, so it sends the first packet to the controller (packet-in).
  2. Is the source host blocked for brute force? Drop it at its switch.
  3. Is it a server port other than 5000? Firewall drop.
  4. Is the source a denied host in config/policy.json? Policy drop.
  5. Otherwise pick a path (static: always s1-s2-s4; dynamic: least loaded) and install a rule for this exact connection on every switch along it, in both directions.
  6. When the server reports transfer_start, re-balance; when a port goes down, move every connection on that link.

Message format

[ 4-byte big-endian length ][ UTF-8 JSON ]           then, for UPLOAD / DOWNLOAD, exactly "size" raw bytes

AUTH     {"op":"AUTH","user":"alice","password":"..."}      -> {"status":"OK","role":"user"}
UPLOAD   {"op":"UPLOAD","name","size","sha256"}            -> {"status":"READY"} <bytes> {"status":"OK"}
DOWNLOAD {"op":"DOWNLOAD","name","offset"}                 -> {"status":"OK","size","sha256","length"} <bytes>
overload                                                   -> {"status":"BUSY","retry_after":1.0}
